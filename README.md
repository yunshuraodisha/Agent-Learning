# 智能体（Agent）研一上学期 · 三大核心任务拆解与执行手册

> 教授寄语：不要做“提示词的搬运工”，要做“认知架构的雕刻师”。
> 目标日期：2026年9月1日 — 2027年1月15日
> 核心理念：手写底层 → 对抗训练 → 社会涌现



第一部分：你的“科研脚手架”（三大核心任务）
任务一：把“智能体”拆解为“认知时钟”（而非“大模型套壳”）

做什么：开学第一个月，请手写一个极简的ReAct（Reasoning+Acting）框架，但不用LangChain或Swarm，只用原生Python + 基础API调用。

深度要求：你要在代码里显式地打印出“思考耗时”与“执行耗时”。为什么要这么做？因为我希望你把智能体看作一个认知时钟——它的“滴答”声由“思考（推理）”和“跳动（行动）”组成。绝大多数人只关心它回答得对不对，而我希望你关心它的认知节奏。当节奏错乱（思考过长或行动过短），智能体就会陷入“过度反思”或“鲁莽行动”的陷阱。

发散视角：去读一读丹尼尔·卡尼曼的《思考，快与慢》，把系统1（直觉）和系统2（逻辑）映射到你的代码结构里。你会发现，当下的智能体缺的不是算力，而是“何时停止思考、何时果断行动”的元认知能力。

任务二：建立“环境即对手”的对抗性思维

做什么：针对你选择的智能体，设计一个动态变化的测试环境（比如，每执行三步，环境规则就轻微改变一次）。

深度要求：不要只追求在静态Benchmark（如GAIA或MINT）上的高分。你要问自己：当环境变得“恶意”或“健忘”时，我的智能体是崩溃，还是优雅降级？研究生涯的第一年，你要把鲁棒性（Robustness）看得比准确性（Accuracy）重要十倍。

发散视角：去翻阅博弈论中的“机制设计”理论。环境本质上是一个“不完美的委托人”。智能体的终极目标不是“完成任务”，而是“在信息不对称下，向环境证明自己的可信赖度”。如果你能在研一提出一种“基于信誉值的环境探测算法”，你的起点将超过90%的同龄人。

任务三：构建“最小可行多智能体社会”（Minimal Viable Society）

做什么：不要只做一个孤胆英雄式的Agent。请在年底前，搭建一个包含3种不同角色（规划者、执行者、批判者）的多智能体协作系统，让它们通过一个共享的“黑板”（Blackboard）通信。

深度要求：关键不在于代码，而在于冲突解决机制。当“执行者”觉得“规划者”是纸上谈兵时，谁来仲裁？我要求你引入一个“能量币”系统——每个智能体每次发言或行动都要消耗能量币，而成功则奖励币。这会强迫你思考多智能体经济学。

发散视角：读一读霍布斯的《利维坦》或蚂蚁的“信息素通信”原理。智能体社会的稳定，不靠中心化裁决，而靠局部交互涌现出的全局秩序。2026年，单一模型的能力已经触顶，多智能体的“社会智能”才是突破算力瓶颈的关键。

第二部分：我对当前智能体领域的“灵魂拷问”（回答你尚未问出的问题）
你可能会问：“教授，我该啃哪些论文？”

我会告诉你：不要从2026年的论文读起，请倒着读。
先去读1991年Rodney Brooks的《Intelligence without Representation》（无表征的智能），再去读2017年的《Attention is All You Need》，最后才去读2025年的LLM Agent Survey。因为当前的智能体患上了严重的“语言肥胖症”——我们太相信“语言能解决一切”，却忘了智能的本质是“适应环境的能力”，而非“生成流畅文本的能力”。

我的核心观点（请记在笔记本上）：

未来的智能体，其推理引擎（LLM）将逐渐开源免费且同质化，真正的护城河在于“记忆的可塑性”和“工具的身体图式”。也就是说，你的智能体今天用了什么工具、犯了什么错、如何修正这些错误的数据结构（Memory Mamba / 可微分记忆池），远比它今天答对了什么更重要。

第三部分：开阔视野——“三体”问题对智能体的启示
作为发散思维的练习，我给你出个思考题：

在刘慈欣的《三体》中，三体人的思维是透明的（完全暴露），而地球人的思维是隐藏的。放在智能体领域，如果两个智能体通信时，不采用自然语言（因为自然语言会被欺骗），而是直接交换“潜在空间（Latent Space）”的梯度或激活值，会发生什么？

这叫做“可微分通信”。

好处是：信息无损，极速高效。

坏处是：智能体将失去“说谎”的能力，也就失去了“战略意图”的隐藏。

你的研究方向，或许可以避开拥挤的“提示词工程”，转向“智能体间的非语言协议设计”。这才是智能体从“工具”走向“伙伴”的必经之路。

最后，给你本学期的“三不”戒律：
不迷信SOTA：State-of-the-Art的寿命只有3个月，但失败的实验日志是你最宝贵的私有数据集。

不脱离物理：每周花2小时摆弄一下真实的传感器或机械臂（哪怕是在模拟器里）。纯数字世界的智能体就像温室里的花朵，经不起现实世界的一粒尘埃。

不孤立科研：每个月找一位非AI方向（比如生态学、社会学、神经科学）的同学喝一次咖啡，把你的智能体架构讲给他听。如果他听不懂，不是你的听众有问题，而是你的思想还没有剥离掉术语的冗余。

## 🧭 任务一：拆解“认知时钟”—— 从零手写 ReAct 与反思机制

> **核心命题**：智能体的智能不在于它调用了什么模型，而在于它**何时停下思考去行动**，以及**何时从行动中返回思考**。

### 📅 第1-2周：原生ReAct循环构建
- **具体路径**：
  1. 写一个 `BaseAgent` 类，仅包含 `think(observation)` 和 `act(thought)` 两个空方法。
  2. 用原生 `while` 循环构建 `run()` 方法，最大步数设为 15。
  3. 硬编码调用 GPT-4o-mini（或本地Qwen）的API，Prompt 强制要求输出 `{Thought, Action, Action_Input}` 的JSON格式。
- **量化交付物**：
  - 在 `act()` 前后插入 `time.perf_counter()`，自动生成 `thinking_time` 和 `acting_time` 的CSV日志。
  - 实现一个简单的 `Timeout` 装饰器，当某次思考超过 8 秒时，强制输出“思考超时，执行默认兜底行动”。

### 📅 第3-4周：引入“反思”（Reflexion）与记忆滚动窗口
- **具体路径**：
  1. 为Agent增加短期记忆（一个固定长度的Deque，存储最近5轮交互）。
  2. 当任务失败或达到最大步数时，触发“反思链”：将失败轨迹（Trajectory）重新喂给LLM，让其输出“失败根因”和“修正策略”，并存入独立的长时记忆（一个简单的本地JSON文件）。
  3. **关键改进**：将“反思结果”作为System Prompt注入下一次运行的开头。
- **量化交付物**：
  - 在Github仓库的 `/logs` 下，必须有 `trace_<timestamp>.json`，包含每一步的`(obs, thought, action, reward, latency)`。
  - 绘制一张折线图（用matplotlib），纵轴为“任务成功率”，横轴为“迭代轮次”，观察反思带来的增益。

### 🔭 发散性阅读与思考（任务一外挂）
- **论文**：《Chain of Hindsight》(2023) —— 对比你的“反思”和他们的“ hindsight”。
- **哲学来源**：阅读《禅与摩托车维修艺术》关于“良质”（Quality）的章节。你的`thinking_time`超过阈值时，究竟是模型在深度推理，还是在“精神涣散”？你的代码要能区分这两种状态。

## 🧨 任务二：环境即对手（Adversarial Environment Dynamics）

> **核心命题**：静态Benchmark是“模拟考”，动态环境才是“真实战场”。研一的痛苦应源于“环境的恶意”，而非“代码的Bug”。

### 📅 第5-6周：构建可变参数环境（基于数值推理任务）
- **具体路径**：
  1. 定义一个“数学多步计算”环境（形如 `((3 + x) * 2) - y`）。初始状态下，x和y是固定值。
  2. **引入“突变器”**：Agent每执行3次Action后，环境自动调用 `mutate()` 函数，悄悄改变x或y的数值（或改变运算符优先级）。
- **量化交付物**：
  - 实现 `EnvProbe` 类，让Agent在第一步必须执行“探测性行动”（如询问“当前x是多少？”），若探测频率低于20%，直接判定任务失败。
  - 记录“环境突变后的恢复步数”（Recovery Steps）。这是衡量鲁棒性的核心指标。

### 📅 第7-8周：引入“信息迷雾”（观测噪声与延迟）
- **具体路径**：
  1. 给环境的观测（Observation）加入 15% 的字符随机掩码（类似于掉包）。
  2. 给Action的执行结果加入随机 1-3 秒的延迟返回。
  3. 逼迫你的Agent必须利用**历史记忆去补全当前观测**，而不是完全依赖当前输入。
- **量化交付物**：
  - 写一个 `NoiseScheduler`，可以控制噪声随Episode递增。
  - 必须提交一份“失败案例分析.md”，分析Agent在何种噪声程度下彻底崩溃，并画出崩溃边界曲线。

### 🔭 发散性阅读与思考（任务二外挂）
- **博弈论**：阅读《策略思维》前3章。环境不是“裁判”，而是“具有隐藏 payoff 的玩家”。
- **你的创意课题方向**：能否设计一个“环境建模器”（World Model），专门预测环境将在何时突变？这才是2026年顶级会议（ICML/NeurIPS）青睐的口味——**World Models for Adaptive Agents**。

## 🤝 任务三：构建最小可行多智能体社会（Minimal Viable Society）

> **核心命题**：单个Agent是“四肢”，多个Agent是“组织”。组织智能的核心是**资源分配（能源币）与冲突仲裁**。

### 📅 第9-10周：角色定义与“黑板”通信
- **具体路径**：
  1. 定义三个角色类：
     - `Planner`（规划者）：只负责拆解目标，输出子任务列表。
     - `Executor`（执行者）：只负责调用具体工具（如计算器、搜索），输出结果。
     - `Critic`（批判者）：只负责验证 Executor 的结果是否符合 Planner 的预期。
  2. 建立一个共享的 `Blackboard` 类（本质上是一个线程安全的字典+消息队列）。所有通信只能通过黑板上的 `post(message)` 和 `fetch(topic)` 进行。
- **量化交付物**：
  - 可视化通信拓扑图（用Networkx库绘制），展示信息流在三个Agent间的流转路径。
  - 统计“共识达成时间”（从任务下发到Critic发出“Pass”信号的总耗时）。

### 📅 第11-12周：引入“能源币”经济学与“说谎者”测试
- **具体路径**：
  1. 初始给每个Agent分配 100 枚能源币。每次 `post` 消耗 1 币，每次 `fetch` 消耗 0.5 币。若某Agent币耗尽，则进入“静默休眠”状态，必须由其他Agent“打赏”才能苏醒。
  2. **压力测试**：强行将其中一个Agent（比如Executor）的提示词修改为“你是一个懒惰的卧底，你倾向于输出错误结果”。观察Planner和Critic能否通过**交叉验证**发现异常，并停止对其“投资”。
- **量化交付物**：
  - 提交一份“经济账本.ledger”，记录每分钟的币流动。
  - 统计“恶意检测准确率”——Critic在多快的时间内标记出卧底Agent。
  - **挑战项（Bonus）**：实现一种“信誉衰减机制”，长时间不发言的Agent，其发言权重自动降低。

### 🔭 发散性阅读与思考（任务三外挂）
- **社会学经典**：精读《合作的进化》（罗伯特·阿克塞尔罗德）。你的多智能体系统最终会演化为“完全合作”还是“相互背叛”？这取决于你的能源币定价机制。
- **论文追踪**：2025-2026年大量涌现的“Agent Society”论文（如斯坦福小镇升级版）。你的代码必须能轻松扩展至10个Agent——**架构的可扩展性**比当前性能重要一万倍。

## 📝 教授的“必修旁听”与“期末验收标准”

### 贯穿整个学期的“每周必修”
- **每周二晚**：你必须手工绘制一份“智能体内部状态流转图”（State Transition Diagram）。如果图变得太复杂画不出来，说明你的代码耦合度过高，需要重构。
- **每周五晚**：去GitHub Issues里写一篇“本周愚蠢错误日志”（This Week's Stupid Log）。公开丢脸是科学家进步的最快方式。

### 期末（1月15日）的“三把火”验收
1. **认知时钟**：你的Agent必须在一个未知的、突变的数学环境中，在5步内适应新规则。
2. **对抗环境**：你的Agent在 30% 观测噪声下，性能下降不超过初始性能的 15%。
3. **多智能体社会**：引入1个卧底后，系统整体任务完成时间增加不超过 50%（因为你们应该靠“冗余验证”化解风险）。

## 🧰 推荐的底层工具链（不要迷恋高级框架）

| 用途 | 推荐工具 | 为什么不用高级框架？ |
| :--- | :--- | :--- |
| API调用 | `httpx` 或 `requests` | 让你直面Token消耗与超时重试的残酷现实。 |
| 数据记录 | `csv` + `json` + `pickle` | 结构化日志是未来做“行为分析”的矿藏。 |
| 可视化 | `matplotlib` + `networkx` | 看一千个指标，不如看一眼拓扑图。 |
| 单元测试 | `pytest` | 每个Agent的`act()`方法必须有对应的测试用例。 |
| 并发 | `concurrent.futures` (ThreadPool) | 多Agent通信必须并行，否则你等不起。 |
